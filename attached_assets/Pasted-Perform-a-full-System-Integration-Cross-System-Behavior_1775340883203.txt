2. DEFINE SYSTEM-TO-SYSTEM RELATIONSHIPS
========================

Create proper behavioral relationships between systems.

Examples of correct relationships:

- user preferences should influence smart offers
- meal plan should influence homepage suggestions
- time of day should influence discovery + map + offers
- social activity should influence discovery and notifications
- live activity should influence map ranking and homepage sections
- premium verification should influence trust + ranking
- business type should influence tags, map markers, and dashboard variation
- instant plans should use live + social + location signals
- auto plans should use behavior + time + social + offers
- monetization should influence visibility ethically, not blindly
- founder dashboard should reflect what the product actually knows

Make these relationships real and consistent.

========================
3. REMOVE SYSTEM ISOLATION
========================

Fix places where a system exists but behaves like an isolated feature.

Examples:
- smart offers exists but does not react to meal plans
- social system exists but does not influence discovery
- heat map exists but does not affect ranking
- profile preferences exist but do not change homepage
- premium trust exists but does not affect place-level presentation
- plans exist but do not influence notifications
- business type exists but does not influence dashboard experience

No important system should remain isolated if it is meant to shape behavior.

========================
4. REMOVE SYSTEM CONTRADICTIONS
========================

Find and fix contradictions between systems.

Examples:
- one system suggests café while another pushes nightlife at the wrong time
- user preferences say vegetarian but offers show meat-heavy places prominently
- social signals say one thing while discovery ranking says another
- meal plan says pizza tonight but homepage ignores it
- premium boost overrides relevance too aggressively
- notifications push irrelevant actions
- business dashboard shows one reality while founder dashboard implies another

All systems must point in the same direction.
