Implement a full production-grade multilingual localization system (i18n) across the entire RestoSmart app.

IMPORTANT:
- This is NOT a simple text replacement task
- This is NOT a partial translation patch
- This is a full internationalization architecture task
- The system must be robust, scalable, and complete
- Do NOT leave mixed-language UI anywhere
- Do NOT hardcode translated strings directly inside components unless part of a clean i18n system
- The app must support both:
  1. automatic device/browser language detection
  2. manual language switching inside the app

==================================================
PRIMARY GOAL
==================================================

Build a complete multilingual translation system so the entire app can run in the user’s language automatically and consistently.

When the app opens:
- it should detect the phone/browser/app language automatically
- and default to that language if supported

Also:
- user must be able to manually switch language from inside the app
- once changed, the app must remember that choice
- all UI text must update completely
- no mixed German/English/French text should remain

==================================================

2. FULL I18N ARCHITECTURE (CRITICAL)
==================================================

Implement a real i18n system across the whole app.

Requirements:
- centralized translation files/resources
- stable translation keys
- no scattered ad hoc translation hacks
- no duplicated translation logic in many components
- no partial/manual page-by-page inconsistent setup

Use a clean architecture such as:
- namespace-based translation files
- feature/module grouping where useful
- shared helper for translation lookup
- locale persistence

This must be scalable and maintainable.

==================================================
3. AUTOMATIC LANGUAGE DETECTION
==================================================

On first app open / first visit:

- detect device/browser language
- if the language is supported, automatically use it
- if unsupported, fall back cleanly to German or the chosen base language

Examples:
- iPhone in French → app opens in French
- browser in English → app opens in English
- unsupported locale → fallback safely

This should work for:
- mobile web
- app shell / installed app behavior if relevant
- browser usage

==================================================
4. MANUAL LANGUAGE SWITCHER
==================================================

Add a clear language switcher in the app.

At minimum:
- visible in settings
- optionally also accessible from a top-level home/header/globe icon if it fits cleanly

The user must be able to switch manually between supported languages.

Requirements:
- language changes immediately
- no reload confusion if avoidable
- selection persists for future sessions
- override manual choice over automatic detection

Examples:
- German user switches to English → app stays English next time
- French phone but user wants German → app respects manual choice
